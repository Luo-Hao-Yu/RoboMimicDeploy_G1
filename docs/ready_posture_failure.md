# Start 后不支撑、Ready 误报的真实记录

## 真实日志证据

用户报告：双脚在地面承重，Start 后经过约 3 秒，终端显示 Ready，但身体仍瘫软。
本轮找到对应的真实报告 `logs/sim2real/real_failure_xmbw8k78.json`：

- 本次退出发生在 **Ready 阶段请求进入 Policy**，异常为 `Robot has not reached the default posture`。
  与更早的 Policy 跟踪误差是不同故障，本次没有成功进入策略。
- 最后约 5.74 秒的命令记录全部处于 Ready。
- 左踝 pitch 目标 −0.3630 rad，末次实测 −0.6224 rad，偏差 +0.2594 rad。
- 右踝 pitch 目标 −0.3630 rad，末次实测 −0.6231 rad，偏差 +0.2601 rad。
- 这段期间左右踝 pitch 变化范围仅约 0.00249 / 0.00060 rad。
- 角度偏差略大于原 A 准入的 0.25 rad，触发拒绝，符合日志。
- 最后一次策略观测的重力投影对应机身倾角约 9.65°。该值不能单独证明异常，
  用户已说明默认姿态本来前倾，本次重点是支撑与关节跟踪情况。

旧版 Ready 仅由 3 秒计时到期置位，并未检查姿态是否到达。
这属于已确认的状态判断缺陷，应将“目标过渡完成”和“实测已达标”分开。

这些日志记录的是软件已成功提交给 DDS 的目标，不是固件逐条确认的命令。
SDK `ChannelPublisher.Write()` 的 True 只说明调用未抛出发送异常，
不能证明机器人固件已接受或执行关节目标。
旧报告没有实际 motor mode 或 tau_est，不能证明电机完全未使能，
也不能仅凭 q 偏差断言需要增大 PD。

按配置 Kp 28.50 Nm/rad 和末次 q/dq 计算，两踝候选 PD 力矩约 7.4 Nm。
这只是计算值，不是实际输出力矩。必须与同一控制阶段真实 tau_est 比较。

## 修正范围

保留原 PD、默认前倾姿态、动作渐入和 0.8 rad 跟踪保护。
没有为了解除报错而改变电机输出参数。

状态流程改为：

```text
waiting → Start → ramp（目标过渡） → settling（检查实测） → ready → 新按 A → policy
```

过渡到目标后，需要以下实测条件连续满足 0.5 秒，并且收到新的有效 LowState，才显示 Ready：

- 所有关节对默认姿态最大偏差 ≤0.25 rad（沿用原 A 准入角度界限）。
- 最大关节速度 ≤0.2 rad/s。
- IMU 角速度范数 ≤0.2 rad/s。

settling 最多持续 3 秒，未达标则报出具体关节并走现有故障退出/阻尼路径。
Ready 后条件变差会撤回至 settling，A 入口也重新检查数据。
不要求机身 pitch=0，不把默认前倾姿态强行改直立。
这些是姿态跟踪准入条件，**不代表通过动态平衡、足底承重或固件控制确认**。

配置项在 `deploy_real/config/g1_23dof.yaml` 的 `ready_*` 字段。

新增记录：每次已发送的 q/kp/kd、实测 q/dq、IMU、motor mode、motorstate 和 tau_est。
发生故障自动保存 `real_failure_*.json`；启用模式下正常主动结束也保存
`real_session_*.json`，便于不必等待报错即可保留观测。
不要把 SDK 原始 motor mode 数值直接解释为已经通过电机输出验证。

另修复了时间采样竞态：推理线程可能在主循环早期取时之后完成动作，
原来的时间计算会把新动作当成“负帧龄”而误报 Stale action；现在在拿到动作后重新取时。
此问题与用户报告的持续瘫软不是同一根因。

## 本轮验证与限制

- 46 项离线测试通过，包括计时结束不能直接 Ready、真实偏差模式拒绝、
  连续达标、新鲜样本、失稳撤销、A 重检和默认倾斜姿态允许。
- 已读取当前机器人 3 秒状态，无电机输出；报告为
  `logs/sim2real/ready_motor_state_readonly.json`，motor mode 原始值均为 0，
  motorstate 故障位均为 0，tau_est 接近零。
- 该只读快照是故障后采样，并非 Start→Ready 同期记录，因此不能由此反推
  故障时是否已使能、是否真正施加 PD。
- 本轮没有执行 Start、控制接管或按 A；尚未修复/验证真实支撑问题。

姿态过渡期间 kp 从零增加，初期支撑能力较弱是代码事实；
Ready 时 kp 已达到配置值。若 3 秒后仍瘫软，需要核查接管后的电机实际模式与力矩响应，
不能只延长等待时间或用 A 强行切入补偿。

## 更新：带电机力矩反馈的真实 settling 故障

新日志：`logs/sim2real/real_failure_uh0ny7an.json`。
这是新的实际运行记录，不是前面的 `xmbw8k78` 报告，也不是仿真。
本次在 settling 等待 3 秒后失败，未进入 Ready/Policy。
最终右踝 pitch 误差 0.264827 rad，大于 0.25 rad；关节速度和机身角速度条件均已满足。

取 settling 最后约 0.989 秒的 45 个采样做对比：

| 关节 | 目标 rad | 实测均值 rad | PD 计算力矩 Nm | 回报 tau_est 均值 Nm |
| --- | ---: | ---: | ---: | ---: |
| 左踝 pitch（槽4） | −0.3630 | −0.6088 | +7.005 | +6.850 |
| 右踝 pitch（槽10） | −0.3630 | −0.6293 | +7.585 | +7.352 |
| 左膝（槽3） | +0.6690 | +0.7478 | −7.764 | −7.996 |
| 右髋 pitch（槽6） | −0.3120 | −0.1546 | −6.326 | −6.033 |

所有采样的 23 个有效 motor mode 均为 1，motorstate 均为 0。
计算采用 contemporaneous q/dq 和本程序提交的 q/kp/kd；
tau_est 是固件回报的估计力矩，不是独立力传感器测量或逐包命令确认。
但多关节的符号和量级一致，有力支持电机正在响应 PD，
使“整个输出链路完全未生效”不再是首要解释。

当前现象更符合承重状态下固定姿态 PD 留有持续跟踪偏差；
若无前馈补偿，非零位置误差本身会产生支撑所需力矩。
尚不能据此确定默认姿态、PD、实际受力和硬件差异各自的贡献，也不能把稳定角度
或小角速度直接解释为机器人无需外部支撑即可平衡。
策略用的 default/action offset 也没有单独经过静态承重姿态控制器验证。

右踝最终超出准入容差约 0.0148 rad（0.85°），但相对目标的总偏差仍约 15.17°。
不能因为超差幅度小就把容差改到 0.27/0.3 来直接进入 Policy。
优先应在仿真和明确支撑条件下验证独立准备姿态/支撑控制，再验证切入；
本轮仅分析日志，没有修改 PD、容差或默认姿态，没有发送电机命令。

`[Reader] take sample error` 是 SDK 读取回调捕获异常时的通用文本，没有异常细节。
从 traceback 和报告可确定主退出原因是 `PostureNotReadyError`，不是读包超时：
故障时 state_age 约 0.20 ms，且最后阶段 tick 持续推进。该 Reader 提示可能发生在
连接清理期间，当前证据不能确定其具体异常。

逐关节统计保存在 `logs/sim2real/settling_pd_analysis.json`。
