## 优先排查方向

操作者确认实验中有吊绳、支架或人手持续支撑。结合上面的跟踪轨迹，
优先怀疑支撑承重或限制机身/腿部运动，使闭环无法完成策略预期的重心转移和迈步。
这仍是有依据的推断，日志没有足底接触力、绳张力或外部支撑测量，无法直接证明。
仅作防坠、正常步态中不持续受力的吊绳，与持续托住机器人是不同条件。

本日志发生于渐入完成后，状态/深度及时，且电机模式全为 1、故障位全为 0。
当前证据不支持把此次错误直接归因于 A 键瞬间跳变、数据超时或完全没有电机输出。
这些指标也不能单独排除其他硬件或模型问题。

近期多个报告重复出现左右踝俯仰误差；`real_failure_21a7a2q7.json` 在零速度指令下
也于 policy 25.55 秒触发左踝保护。因此只减小前进速度并不能保证解决。

PD 策略的位置目标也承担产生力矩的作用，并不要求承重关节每一时刻精确跟踪。
目标为正、实测为负本身不能证明动作符号或映射错误；
误差达到现有保护阈值说明需要核查执行条件和保护适用范围。

## 处理顺序

1. **先处理外部约束。** 在具备独立停止和防坠条件的受控实验中，
   由现场操作者确认脚底实际承重，防坠装置允许正常重心转移、机身运动和抬脚。
   不直接拆掉防坠装置，也不为追踪目标强行牵拉机器人。
   若必须持续托住机器人，则先做默认姿态/受支撑条件的响应检查，
   不把该条件下的行走策略表现作为自由步态测试。
2. **先零指令验证，再请求前进。** Ready 后摇杆回中进入 policy，
   先观察是否形成稳定、可重复的步态和踝部响应；
   通过后再由操作者逐渐增加前进指令，避免直接推到本日志约 0.256 m/s。
   零指令不等于策略停止输出动作，也不是稳定保证。
3. **若条件修正后仍复现，先对齐模型与执行链。**
   比较真实姿态、相机安装/深度、关节零位和方向、硬件版本、PD 与固件限幅；
   在相同 MuJoCo 模型中比较原仿真控制和真机 Controller 的
   位置限幅、6 rad/s 限速、渐入及延迟对步态和误差分布的影响。
   当前原仿真直接把网络目标送入 PD，真机还修改目标，两者执行链不同。
   单个故障样本不能判定这些差异各自贡献多少。
4. **有对照数据后才调整控制参数或重新训练。** 不直接增大 kp、缩小 action scale、
   反转踝关节符号、把目标夹到实测附近或删去 0.8 rad 保护；
   这些操作会改变策略使用的动力学或掩盖持续偏差。
   若确认正常自由步态本身需要较大 PD 误差，应先用仿真与受控实测评估
   误差持续时间、力矩、接触和姿态，再设计适当的保护，不能只修改一个阈值。

官方普通 RL 示例也区分“悬吊准备”和“脚接地、允许运动后开始步态”，
并要求稳定后逐渐放松吊绳以提供运动空间；这不等于本 Parkour 策略已经通过实机验证。
